## 我做了什么

### spec-analyze — 每天都在用

我写完需求，交给 coding agent，它总是猜错边界条件。

Agent 不会问"这个边缘情况怎么处理？"它直接选一个方案就开干。我在 review 时发现了，来回修，浪费一轮时间。

于是我写了个需求分析引擎。在 coding agent 看到需求之前，它先经过多个角色视角 —— 产品、架构、用户体验、风险 —— 每个视角都挖出盲区和假设偏差。

产出的规格说明已经标注好了边缘情况。Agent 第一次跑就对的概率高了很多。

### project-knowledge — 会话连续性

Claude Code 每次新会话都不记得你的项目。前 10 分钟都在重新解释架构、命名规则、设计决策。

这个 skill 扫描任意代码库，生成 `.claude/knowledge/` 目录 —— 索引、术语表、架构要点、参考文档。Agent 启动时自动加载，不需要重新交代上下文。

### spec-sdd — 方法论

这套规范总结了我做 AI 辅助开发的方式：

**规格 → 方案 → 实现 → 验证**

每个阶段都有完成标准。上一阶段没过，下一阶段不开。它防止了 AI 辅助开发中最贵的错误：用极快的速度做错的东西。

MIT 协议开源。

### llm-knowledge-base

我的文档散落在各处 — Lark、PDF、网页、会议记录。我想要一个地方搜遍所有内容。

于是搭了一个自托管的知识库。支持 15+ 种文件格式导入，通过 Microsoft MarkItDown 转成 Markdown，构建带 `[[双向链接]]` 的 Obsidian 维基，还可以对你的知识库做问答。

114 次提交。Docker compose 重写了不知道多少次。
